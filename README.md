# Eventify - Frontend

Веб-інтерфейс для платформи **Eventify**, призначений для перегляду подій, артистів, майданчиків та інформації про проєкт. Фронтенд працює як окремий клієнт і взаємодіє з Django REST API через асинхронні `fetch`-запити.

---

## 🌐 Використовувані порти та адреси
- **Фронтенд (клієнт):** запущено на `http://127.0.0.1:5500` (або `http://localhost:5500`)
- **Бекенд (API):** працює на `http://127.0.0.1:8000/`

---

## 📄 Структура сторінок та функціонал

1. **Реєстрація (`register.html`):** Форма для створення нового акаунта з перевіркою валідації полів, обмеженням на символи та перевіркою збігу паролів.
2. **Логін (`login.html`):** Сторінка авторизації користувача. Авторизовані користувачі не можуть сюди потрапити (автоматично перенаправляються на сторінку контенту).
3. **Головна сторінка (`index.html`):** Публічний доступ. Каталог подій, перегляд інформації, доступний неавторизованим користувачам.
4. **Сторінка події (`event-detail.html`):** Детальна інформація про конкретний захід (дата, час, опис, вартість, пов'язані артисти та локація), а також можливість додавання квитків у кошик.
5. **Сторінка артистів (`artists.html` / `artist-detail.html`):** Перелік усіх виконавців та детальний перегляд інформації про конкретного артиста разом із списком його майбутніх подій.
6. **Сторінка майданчиків (`venues.html` / `venue-detail.html`):** Каталог концертних залів, клубів чи театрів із можливістю переглянути деталі локації та події, які там відбуватимуться.
7. **Особистий кабінет (`profile.html`):** Захищена сторінка з інформацією про користувача та можливістю редагування особистих даних (доступна лише залогіненим користувачам).
8. **Інформаційна сторінка «Про нас» (`about.html`):** Контактні дані платформи, правила відвідування заходів та умови повернення квитків.

## 🧠 Поведінка та клієнтська логіка

- **Захист маршрутів:** Неавторизованого користувача при спробі відкрити захищену сторінку (профіль) автоматично перенаправляє на сторінку логіну з передачею параметра `next` у URL. Після успішного входу користувача повертає назад на ту сторінку, з якої його перенаправило.
- **Динамічний інтерфейс:**
  - Неавторизований користувач бачить кнопку «Увійти» і не бачить кнопку «Вийти».
  - Авторизований користувач бачить кнопку «Мій профіль», кнопку «Вийти» і не бачить кнопки «Увійти».
- **JWT & Token Refresh (`apiFetch`):** Токени (`access` та `refresh`) зберігаються в `localStorage`. Якщо `access`-токен закінчується (бекенд повертає статус `401`), кастомна функція`apiFetch` автоматично надсилає `refresh`-токен на сервер для отримання нового `access`-токена, не змушуючи користувача заходити в систему наново. При виході з акаунта (`logout`) токени повністю видаляються з клієнта.

## 🚀 Як запустити проєкт

1. Переконайтеся, що у вас запущений бекенд-сервер (Django) на порті `8000`.
2. Клонуйте або відкрийте цей репозиторій у вашому терміналі/редакторі коду.
3. Запустіть проєкт одним із зручних способів:
   - **Через Node.js (Live Server):** у кореневій папці фронтенду виконайте команду в терміналі:
     ```bash
     npx live-server --port=5500
     ```
   - **Через розширення у VS Code:** відкрийте файл `index.html`, натисніть правою кнопкою миші та виберіть **"Open with Live Server"**.
4. Проєкт автоматично відкриється у браузері за адресою `http://127.0.0.1:5500` і почне успішно завантажувати дані з бекенду (налагоджено підтримку CORS).
